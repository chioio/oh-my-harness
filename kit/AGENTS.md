# AGENTS.md

这是目标项目中的共享入口文件，可提交到远端仓库。

## 读取顺序

agent 在目标项目中必须按以下顺序解析：

1. 先读取本文件
2. 如果存在 `AGENTS.local.md`，必须继续读取它
3. 如果不存在 `AGENTS.local.md` 但存在 `_harness/`，则将 `_harness/` 视为项目内共享 harness 并继续路由
4. 如果检测到本项目仍存在补充占位，必须继续完成项目内补充，而不是忽略

## 本文件的职责

- 提供项目级共享入口
- 告诉 agent 本项目存在本地私有增强层
- 保持内容简洁，不在此承载完整个人 harness

## 本地增强层

若 `AGENTS.local.md` 存在：

- 它属于当前操作者的本地私有增强层
- agent 必须继续解析它
- 不应将其视为可忽略文件

## setup 后的期望状态

本项目在 setup 后通常会是以下两种模式之一：

- 默认私有模式：
  - `AGENTS.md`（共享，可推送远端）
  - `AGENTS.local.md`（本地私有，不共享）
  - `_harness/`（本地私有，不共享）
- 可提交模式：
  - `AGENTS.md`（共享，可推送远端）
  - `_harness/`（共享，可推送远端）
  - 可不存在 `AGENTS.local.md`

## 补充占位规则

若存在本地补充占位文件，表示该项目的私有 harness 仍需继续补全。

agent 在发现该占位后应：

1. 明确这是项目内的本地补充阶段
2. 读取相关说明文件
3. 继续完成本项目所需的 `_harness/` 与本地规则补充

## 默认原则

- 共享信息留在 `AGENTS.md`
- 私有模式下，本地增强留在 `AGENTS.local.md` 与 `_harness/`
- 可提交模式下，`_harness/` 可直接作为共享 harness
- 先读共享入口，再读本地增强或共享 harness
- 只读取最小必要上下文
